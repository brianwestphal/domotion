# Major-release visual capture checklist

This is the maintainer handoff for refreshing Domotion's public visuals before a
major release. It separates deterministic in-repository demo generation from
the human capture and visual-approval pass. Automation must remain headless:
set `DOMOTION_NO_OPEN=1`, and pass `--no-open` to SVG Review or SVG Scrubber.

## 1. Regenerate the canonical demo set

From the repository root:

```bash
DOMOTION_NO_OPEN=1 npm run demos:examples
DOMOTION_NO_OPEN=1 npm --prefix site run build-demos
```

The first command refreshes the committed example outputs used by the README
and site. The second rebuilds `site/public/demos/` from those artifacts, the
animate-example goldens, the template gallery, and the committed full-app
captures. Review the resulting Git diff; generated SVG changes must have an
explainable source change and must not be accepted solely because regeneration
succeeded.

## 2. Approve the launch surfaces

Capture or inspect these assets at their intrinsic size and at 2×. For every
animation, inspect time zero, a representative motion midpoint, the payoff, and
the final frame immediately before the loop. Then watch one complete loop.

| Done | Surface | Canonical asset | Approval focus |
| --- | --- | --- | --- |
| - [ ] | README wordmark | `examples/output/domotion-word-demo.svg` | All typographic variants fit the fixed canvas; no clipped ascenders/descenders; loop has no flash. |
| - [ ] | README and site hero | `examples/output/hero-product-demo.svg` | KPI entrance, chart growth, typed search, click feedback, hierarchy, and final hold all remain legible. |
| - [ ] | Fidelity proof | `site/demo-assets/fidelity/wikipedia-fidelity.png` | Labels remain honest at native size and 4×; do not imply cross-platform byte/pixel identity beyond the captured environment. |
| - [ ] | Capability showcase | `examples/output/showcase-rendering.svg`, `transition-tour.svg`, `transition-mixed.svg`, `storyboard-demo.svg` | Font/layout fidelity, every transition family, four-scene narrative, and clean loop/cut boundaries. |
| - [ ] | Video export proof | `examples/output/transition-tour.svg` → `transition-tour.mp4` | Run `DOMOTION_NO_OPEN=1 npx tsx examples/svg-to-video-demo.ts`; verify the full loop, dimensions, and final hold. |
| - [ ] | Terminal showcase | `examples/output/terminal-onboarding.svg`, `terminal-window-scroll.svg` | Command readability, window chrome, scroll timing, and no cropped final line. |
| - [ ] | Template gallery | `examples/output/templates/*.svg` | Representative chart, kinetic text, device mockup, quote, CTA, counter, and background loop at desktop plus one vertical format. |

Use deterministic headless derivatives for close inspection:

```bash
DOMOTION_NO_OPEN=1 npx svg-to-image examples/output/hero-product-demo.svg -o /tmp/domotion-hero-start.png --at 0
DOMOTION_NO_OPEN=1 npx svg-to-image examples/output/hero-product-demo.svg -o /tmp/domotion-hero-mid.png --at 3500
DOMOTION_NO_OPEN=1 npx svg-to-image examples/output/hero-product-demo.svg -o /tmp/domotion-hero-2x.png --at 7000 --scale 2
DOMOTION_NO_OPEN=1 npx svg-to-video examples/output/hero-product-demo.svg -o /tmp/domotion-hero-review.mp4
```

If the exact payoff time moves, use `svg-scrubber ... --no-open` and its printed
local URL to find it; do not let an automated run open the desktop browser.

## 3. Refresh full-application captures

The Glassbox and Hot Sheet assets are copied from their own repositories, not
generated by this checkout. Follow `site/demo-assets/apps/README.md`, then copy
the approved source artifacts into `site/demo-assets/apps/`:

- [ ] Glassbox: refresh the full review storyboard and risk-mode still.
- [ ] Hot Sheet: refresh the board, Up Next, and dashboard captures.
- For each app, verify the visible product name/version, seeded data, privacy of
  any sample content, complete-loop pacing, and the first frame used when a host
  sanitizes SVG animation.

Record the source commit beside the release notes or capture PR so provenance is
recoverable. Do not silently reuse an old asset when its source app changed.

## 4. Verify every site reference

Run the site build and confirm that every `/domotion/demos/...` reference in the
content resolves under `site/public/demos/`. Review the homepage and showcase at
desktop and narrow widths, checking intrinsic aspect ratios, lazy-load layout,
alt text, and the static first frame on non-animating hosts.

```bash
DOMOTION_NO_OPEN=1 npm --prefix site run build
```

The public copy must describe the current rendering contract accurately:
captured glyph data is embedded, viewer-side native font fallback is not used,
and consumer antialiasing/hinting may still vary slightly.

## 5. Record the approval

The release handoff must name:

- the regenerated assets and source commits;
- the exact still times inspected;
- which complete loops were watched;
- desktop and narrow site routes checked;
- any asset deliberately retained, with the reason;
- any unavailable visual check, without claiming it passed.
